# NPC 智能体：Push 前代码审查流程

> 版本 v1.0 | **规则：完成一个阶段性任务、准备 push 之前，必须走完本流程；审查不通过 = 不 push。**
> 本文件既是流程定义，也是检查清单与报告模板。

---

## 1. 时机

- 每次 push 前（对应 RA 路线图的一个阶段性任务完成时）；
- 阶段验收项完成时，随验收一并进行（验收 = 测试门禁 + 本审查）。

## 2. 流程（四步）

```
① 自动门禁  scripts/check-gate.sh（依赖方向 → 构建 -Werror → ctest → 格式）
      ↓ 全绿
② 逐条自查  按 §3 检查清单核对（耦合/线程/内存性能/注释/命名/冗余/测试）
      ↓
③ 审查报告  写入 docs/reviews/<日期>-<阶段名>.md（模板见 §4）
      ↓
④ 修复闭环  清单有 N 条不通过 → 修复 → 回到 ①；全过 → 提交 + push
```

**红线项**（任一条命中，直接打回，无商量）：
1. 依赖方向被破坏（npc_agent include game_adapter / 接口层出现第三方类型）；
2. 违反线程契约（工作线程触碰框架对象、驱动线程阻塞等待）；
3. 接口层（RA-§3）改动但 `docs/roadmap-architecture.md` 未同步（§9 定案表 / §14 变更记录）；
4. `-Werror` 构建有警告；
5. 提交中出现注释掉的死代码；
6. 能力模块持有 `IWorld`/`IAgentBody` 指针（Blackboard-only 契约）。

## 3. 检查清单（每项对应编码/测试规范条款）

### A. 耦合与可移植性（最高优先级）
- [ ] 依赖方向：核心未 include 适配层/游戏代码（CS-§1.3、门禁已查）
- [ ] 接口层只含 POD + std，无 glm/EnTT/引擎类型（CS-§1.3）
- [ ] 新增模块无环形依赖；对外只有一个公共头（CS-§6.3/6.4）
- [ ] 无平台 API 进核心；条件编译集中于 config/（CS-§11）

### B. 线程与并发
- [ ] 每个跨线程边界都有注释标注契约（CS-§5.1 线程契约标签）
- [ ] 回调/事件处理器不再入 tick 排空循环（CS-§8.4）
- [ ] 驱动线程无阻塞等待（CS-§8.2）

### C. 内存与性能
- [ ] 无裸 new/delete；所有权清晰（CS-§7.1）
- [ ] 传参/返回符合规则，无隐藏拷贝（CS-§7.2/7.3）
- [ ] 循环内无分配、无隐式拷贝；reserve/复用到位（CS-§7.4）
- [ ] 热路径零分配，无非必要虚调用/`std::function`（CS-§7.5）
- [ ] 无大循环隐患；非平凡函数标了复杂度（CS-§7.6）
- [ ] 性能改动有依据（CS-§7.8）

### D. 注释与命名
- [ ] 新增公共 API 文档注释完整（用途/前置/线程契约/所有权/复杂度）（CS-§5.1）
- [ ] 注释是"为什么"，无翻译式注释；TODO 三要素齐全（CS-§5.2/5.4）
- [ ] 无魔数；命名符合 §4 表（CS-§4/5.3）

### E. 冗余与质量
- [ ] 无死代码、无注释掉代码、无未用参数/分支（CS-§1/§5.5）
- [ ] YAGNI：没有为"以后可能"写的代码（CS-§1）
- [ ] 错误处理路径完整（配置 fail-fast、LLM 降级）（CS-§9）

### F. 测试
- [ ] 新增公共 API 有测试；bug 修复带复现测试（TS-§3/§5）
- [ ] 测试确定性、互不依赖（TS-§1.3/§4.4）
- [ ] 阶段验收场景测试存在并通过（TS-§3 scenarios 行）

## 5. 角色说明

- 本仓库由 AI 编码代理实现时，代理**必须**：完成阶段任务后先跑门禁、逐条自查、输出报告，再执行 push；
- 人工评审时使用同一清单，结论写进同一报告；
- 报告与代码同仓提交（`docs/reviews/`），保证每次 push 都有据可查。
