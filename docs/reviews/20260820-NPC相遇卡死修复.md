# 测试记录：NPC 相遇卡死与持续监测（2026-08-20）

## 用户反馈
> "我在测试的时候你为什么退出而不是持续监测状态？现在木箱没有显示效果，
> NPC 路径有交集碰面就卡死，没有重新规划"

## 处理过程记录

### 1. 窗口状态与"退出"问题
- 排查发现同时存在**两个 godot 窗口进程**：旧进程（`bash-9` 启动，运行上一版
  代码，无反馈气泡）与新进程（`bash-10`，最新版）。用户看到的是旧窗口——
  旧版木箱无气泡提示、位置逻辑不同，造成"没反应/没效果"。
- 已 kill 旧进程，保留新进程；**新窗口持续运行中**（不再反复退出重启）。

### 2. 木箱没有显示效果
- 代码检查：木箱 ColorRect + add_child 正常；最新版已加玩家头顶反馈气泡
  （成功"已放置木箱"0.5s / 失败"四周都被挡住"0.9s）。
- 结论：旧窗口无气泡；新版窗口验证通过（探针实测气泡可见、文本正确）。

### 3. NPC 相遇卡死（本次核心修复，R10-12）
- **根因**：寻路（`world_.find_path`）只把静态障碍（建筑/树/木箱）当障碍，A*
  路径会穿过其他 NPC 的当前位置。两个 NPC 路径交叉相遇时，`blocked_check`
  双方都检测到对方 → 互相等待（`moving_` 保持 true），而每帧重新规划的路径
  仍穿过对方 → 死锁，直到状态超时（如 search 3.5s）才脱身。
- **修复**：新增 `find_path_avoiding(self, from, to)`：
  - 寻路前临时把其他 NPC 与玩家的当前位置**膨胀为 3×3 单元（0.75u）**阻塞
    为障碍（覆盖 `kAgentRadius=0.35u` 半径），求路径后恢复网格；
  - A* 路径从智能体旁至少 0.375u 经过，`blocked_check`（0.35u）不再挡绕行路径；
  - `plan_paths_and_report` 与 `place_obstacle` 重规划均改用动态避障寻路。
- **验证**（探针：枪声后守卫 search 与平民 flee 路径交叉）：
  - 修复前：守卫在 (-2.13,0) 卡 4 秒（f=120→360 不动），直到 search 超时回 idle；
  - 修复后：f=120 擦肩（dist 0.45u），f=180 绕行，f=240 已到 search 目标附近，
    平民正常 flee 到掩体，双方最小间距 >0.35u；
  - smoke_town 11 链路全 PASS；smoke_test/alt/bad 全 PASS；门禁 5/5 全绿。
